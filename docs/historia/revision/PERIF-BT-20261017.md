# PERIF-BT — WCN6750 Bluetooth: vendor vs mainline (17-oct-2026)

## Resumen (≤350 palabras)

**Vendor (cómo funciona hoy).** El nodo `/soc/bt_wcn6750` (`qcom,wcn6750-bt`) es de PLATAFORMA y lo toma el driver techpack **btpower** (`soc:bt_wcn6750` → driver `bt_power`, crea `rfkill0 bt_power`): solo gestiona GPIOs y reguladores. El transporte real lo abre el **HAL QTI** (`android.hardware.bluetooth@1.1-service-qti`, IBtTpi) sobre **`/dev/ttyHS0` = `888000.qcom,qup_uart`** (`qcom,msm-geni-serial-hs`, propietario grupo `bluetooth`, wakeup RX = gpio43): HCI-UART H4/QCA (kernel vendor 6.1.138 carga `hci_uart.ko` con protocolo QCA). **BT no pasa por icnss2** (eso es solo WLAN). 8 supplies (aon/dig/rfacmn/rfa0p8 → SMPB3 s3; rfa1 → SMPB1; rfa2 → SMPB2; ipa-2p2 → PM735A S3; io → LDOB7), reset **TLMM 156**, sw-ctrl **80**, wl-reset compartido **35**. BT estaba apagado en la cosecha (`/sys/class/bluetooth` vacío; no se tocó).

**Mainline (nuestro árbol k52-L16, kernel 7.2.0-rc2).** `hci_qca.c` SÍ soporta `qcom,wcn6750-bt` como **serdev** (`qca_soc_data_wcn6750`: 9 vregs, wideband speech + LE states). UART correcto: **`uart10` serial@888000** (`geni-uart`, pins 40/41 CTS-RTS + 42/43 TX-RX, `qup1_se2`) — coincide con el 888000 del vendor. `uart5` a94000 sigue siendo consola (serial0), NO tocar. FW: el chip es **ROM 1.2** (`BTFW.MOSELLE.1.2.0`) → mainline pide **`qca/msbtfw12.mbn` + `qca/msnv12.bin`**; linux-firmware (Arch) solo trae revisión 11, así que **extraje el par del vendor** (partición `bluetooth_a`, montada en `/vendor/bt_firmware/image`) vía `/data/local/tmp` → `build/android/msbtfw12.mbn` (109248 B, sha256 `3efbd7fa…`), `msnv12.bin` (6206 B, `52553c8a…`), `msbtfw12.ver`. Config ya apta en k37.config (`BT=m`, `BT_QCA=m`, `BT_HCIUART=m`, `HCIUART_QCA=y`, `SERIAL_DEV_BUS=y`).

**Plan:** fragmento DT estilo wifi: `&uart10 okay` + nodo `bluetooth` con `enable-gpios <&tlmm 156>`, `swctrl-gpios <&tlmm 80>`, las 9 supplies mapeadas a los reguladores rpmh del DT base vendor, `max-speed <3200000>`; copiar fw a `/lib/firmware/qca/` del rootfs; marcador = `hci0` + `QCA controller version 0x…` en dmesg. Riesgo: GPIO 156 vs `bt-enable` del `pwrseq-qcom-wcn` del payload WiFi (parche l21 ya lo tolera); vddasd exigida por bulk_get de 9 vregs.

## 1. Transporte vendor (evidencia)

- DT (`/tmp/dtfull/base`): `bt_wcn6750` sin UART padre; props: `compatible=qcom,wcn6750-bt`, `qcom,bt-reset-gpio=<tlmm 0x16b 156>`, `qcom,bt-sw-ctrl-gpio=<tlmm 80>`, `qcom,wl-reset-gpio=<tlmm 35>`, `mpm_wake_set_gpios=<80>`, `pinctrl-0=bt_en_sleep` (phandle 0x494), 8× `qcom,bt-vdd-*-supply`+`-config` (min/max uV, load). Sin `qcom,icnss`/tz refs.
- Únicos UART en el DT vendor: `a94000` = `geni-debug-uart` (ttyMSM0, consola) y `888000` = `msm-geni-serial-hs` (ttyHS0, wakeup irq tlmm 43, wakeup-byte 0xFD). Ninguno tiene nodo hijo `bluetooth`.
- dmesg (`01-dmesg.txt`): `bt_power_probe:send platform data of btpower` (línea 4293), `btpower_register_slimdev`, `888000.qcom,qup_uart: ttyHS0 … is a MSM` (3171), HAL `vendor.bluetooth-1-1-qti` arrancado (6758), `console=ttynull` en cmdline.
- En vivo: `/sys/class/bluetooth` vacío (BT off), `/dev/ttyHS0` (488:0, grupo bluetooth), `soc:bt_wcn6750` con driver `bt_power` y suppliers a `smpb1/smpb2/smpb3/ldob7/smpe3`.

## 2. Mainline (k52-L16-tree)

- `drivers/bluetooth/hci_qca.c`: match table incluye `qcom,wcn6750-bt` (línea 2781). Probe serdev: sin `enable-gpios` intenta `pwrseq` "bluetooth"; con `enable-gpios` → 9 regulators + `bt_en` ("enable", opcional) + `sw_ctrl` ("swctrl", **obligatorio** para 6750).
- `drivers/bluetooth/btqca.c`: WCN6750 → `qca/msbtfw%02x.mbn` (ELF) con fallback `.tlv`; NVM `qca/msnv%02x.bin` (rom_ver leído del chip: 1.2 aquí).
- Binding `qcom,wcn6750-bt.yaml`: required vddaon/rfa0p8/rfa1p2/rfa1p7/rfacmn; ejemplo con `firmware-name`, `max-speed <3200000>`.
- DT nuestro: `uart10` (888000, pinctrl `qup_uart10_default`+`qup_uart10_cts_rts`, gpio42/43/40/41, `qup1_se2`) status **disabled**; `uart5` a94000 = consola (aliases serial0, stdout-path) — ya okay en uke.dts. Sin colisión de pines (táctil SPI a90000, audio i2c a80000).
- pinctrl-palawan: `[156] PINGROUP(…, egpio)` — pin existe como GPIO (mismo patrón que el resto), pin 80 normal.

## 3. Firmware

- Chip ROM 1.2 → `msbtfw12.mbn`/`msnv12.bin` (BTFW.MOSELLE.1.2.0-00268). Vendor también embarca hmtbtfw10/20+hmtnv* (WCN7850, NO aplica) y msnv10 (rev 1.0).
- linux-firmware local (`/usr/lib/firmware/qca/`): solo `msbtfw11.mbn/msnv11.*` — insuficiente; usar los extraídos del vendor.

## 4. Plan de port

1. **DT fragmento** (mismo pipeline fdtoverlay que los frags wifi del dtbo s277): `&uart10 { status="okay"; };` + `bluetooth` bajo uart10:
   ```
   bluetooth { compatible = "qcom,wcn6750-bt";
     enable-gpios = <&tlmm 156 0>; swctrl-gpios = <&tlmm 80 0>;
     vddio-supply   = <&pmxr2230_l7>;
     vddaon-supply  = <&pmxr2230_s3>; vddbtcxmx-supply = <&pmxr2230_s3>;
     vddrfacmn-supply = <&pmxr2230_s3>; vddrfa0p8-supply = <&pmxr2230_s3>;
     vddrfa1p7-supply = <&pmxr2230_s1>; vddrfa1p2-supply = <&pmxr2230_s2>;
     vddrfa2p2-supply = <&pmr735a_s3>;
     max-speed = <3200000>; };
   ```
   (`vddasd` solo si `regulator_bulk_get` de los 9 falla → añadir a `pmr735a_s3`.)
2. **Kconfig**: verificar en la config L activa lo que k37.config ya tenía: `BT=m`, `BT_QCA=m`, `BT_HCIUART=m`, `BT_HCIUART_H4/QCA=y`, `BT_HCIUART_SERDEV=y`, `SERIAL_DEV_BUS=y`.
3. **Firmware a rootfs**: `build/android/msbtfw12.mbn + msnv12.bin → /lib/firmware/qca/` (ampliar paquete tipo `paquete-firmware-wlan.sh`).
4. **Verificación**: dmesg → `Bluetooth: hci0: QCA controller version 0x…`; `/sys/class/bluetooth/hci0`; `bluetoothctl list/power on`; rfkill bt desbloqueado. Con BT encendido: `sw_ctrl` (gpio80) debe leer 1.
5. **Riesgos**: (a) GPIO 156 compartido con `bt-enable` del `pwrseq-qcom-wcn` del payload WiFi — el parche `l21-wifi-btgpio.diff` ya tolera que el pwrseq no lo obtenga; asegurar orden/carga del módulo pwrseq. (b) GPIO 156 flagged egpio en pinfunc (la causa-raíz WiFi ya lo documentó); si el TLMM rechaza el gpio, probar sin `enable-gpios` (camino pwrseq) o poke pinctrl. (c) consola = uart5, no tocar. (d) HAL/vendor partition no interfiere en el port.
