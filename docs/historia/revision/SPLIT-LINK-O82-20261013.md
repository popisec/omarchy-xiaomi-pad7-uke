# H2-reserva cerrada: ¿Android programa `SPLIT_LINK` para el o82?

**Fecha:** 13-oct-2026. **Método:** 100% estático y offline (decompilado `build/vendor-re/decomp/`,
`llvm-objdump --arch-name=aarch64` + `readelf -rW` sobre
`~/proyectos/ubuntu-uke/stock/modules/msm_drm.ko`, DT en `build/evidencia/`).
Cero escrituras en la tablet, cero commits (por encargo).

**Veredicto: NO.** Sin `qcom,split-link-enabled` en el DT del o82, el byte que gatea el write
queda a 0 y Android salta la programación de `SPLIT_LINK` exactamente igual que mainline.
**H2 decae a "paridad por omisión mutua". Ninguna acción en mainline.**

## 1. Cadena causal completa (4 eslabones)

**E1 — El write es condicional.** `dsi_ctrl_hw_cmn_host_setup` (`.ko:0x12cfec`,
`build/vendor-re/decomp/dsi_ctrl_hw_cmn_host_setup.c:20-33`): el write a `SPLIT_LINK`
(`0x330`, base `0x503000` + variantes `0x503010`/`0x503100` por sublink + `EN=1`) solo
ejecuta `if (*(char *)(cfg + 0x38) != '\0')`. Los bytes hermanos `cfg+0x39` (swap) y el
int `cfg+0x48 == 2` solo eligen variante; con el gate a 0 no se toca el registro.

**E2 — El `cfg` de E1 es el `host_config` + 4.** `dsi_ctrl_setup.c:27` llama a
`host_setup(hw, ctrl+0x5b4)`; `dsi_ctrl_update_host_config.c:141` había hecho
`memcpy(ctrl+0x5b0, host_config, 0x130)` con el buffer que le pasó
`dsi_display_set_mode.c:280-288` (el mismo que llenó `get_host_cfg`, `:183`).
Luego gate = `host_config+0x3C`.

**E3 — `host_config+0x3C` ← `panel+0x4a0`.** `dsi_panel_get_host_cfg_for_mode`
(`.ko:0x15523c`): `0x1552a8: ldr x9,[x22,#0x4a0]` / `0x1552b8: stur x9,[x19,#0x3c]`
(copia de 8 B; el byte bajo es el gate). Consistente con
`dsi_ctrl_update_host_config.c:44-48`, que usa `param_2[0xf]` (byte `0x3C`) como
"split activo" y `param_2[0x11]` (byte `0x44` = `lanes-per-sublink`) como nº de lanes.

**E4 — `panel+0x4a0 = 1` ⟺ prop `qcom,split-link-enabled` en el nodo del panel.**
En `dsi_panel_get` (`.ko:0x14f214`):
- `0x14fd5c/0x14fd60`: relocs `R_AARCH64_ADR_PREL_PG_HI21/ADD_ABS` → `.rodata+0x106f2`
  = `"qcom,split-link-enabled"` (offset de fichero `0x2781a`, verificado con `strings`/`python`).
- `0x14fd88: blr` (read_bool) → `0x14fd8c: tbz w0,#0 → 0x14feb0` (rama false: log
  `"Split link is not supported"`, `w8=0`); rama true: parsea `qcom,sublinks-count`
  (dflt 2 → `panel+0x4a4`), `qcom,lanes-per-sublink` (dflt 2 → `panel+0x4a8`),
  `qcom,split-link-sublink-swap` (→ `panel+0x4a1`), `w8=1`.
- `0x14fee4: strb w8,[x19,#0x4a0]` — el flag enabled.

(Nota: `qcom,split-link-supported`, leída en `.text:0x137108` dentro de
`dsi_ctrl_dev_probe`, es de nivel display y no gatea este write.)

## 2. El DT del o82 no trae ninguna de las 4 props

`grep -ri split` → 0 coincidencias en: nodo panel
`.../qcom,mdss_mdp@ae00000/qcom,mdss_dsi_o82_42_02_0b_dualdsi_dsc_vid/` (nivel panel y
sus 3 subnodos `qcom,mdss-dsi-display-timings/timing@{120,90,144}` — timing@120 tiene
51 props, ninguna split), nodo hermano `o82_36_02_0a`, `qcom,dsi-display-primary`,
`qcom,dsi-display-secondary`, `qcom,mdss_dsi_ctrl{0,1}`, y en **todo** `dt-r15/`.
En `stock-dt/stock2-Cliffs7P-uke.dts` el único `split` es el no-relacionado
`qcom,sde-has-src-split` (`:15579`, lado MDP). Contraste: los bool-true sí aparecen
como ficheros vacíos (`panel-broadcast-mode`, `cmd-sync-wait-broadcast`,
`tx-eot-append` presentes); de `split-link-*` no hay ni el fichero.

Por tanto `panel+0x4a0 = 0` → `host_config+0x3C = 0` → E1-false → **Android tampoco
escribe `0x330` para el o82**. El valor candidato `0x503001` del informe de comparación
es correcto *para un panel con split*, pero inaplicable aquí.

## 3. Consecuencia para la comparación Android-vs-mainline §H2

- H2 queda **refutada para el o82** (no "alta si aplica": no aplica). El ciclo 3 de la
  tabla (`SPLITLINK ← 0x503001`) **no debe ejecutarse**: programar split-link sin que
  Android lo haga rompería la paridad en vez de restaurarla.
- El byte per-mode `priv+0x1c90` → `host_config+0xE0` (objdump `0x155354-0x155364`;
  default 0 en `dsi_panel_get_mode.c:425`, leído en `update:76-77` para elegir fórmula
  de clocks) también queda a 0 en o82 por la misma ausencia de props; solo afecta al
  cálculo de bit-clock en Android, no a ningún write de registro. Sin acción.
- Residual no bloqueante: no se resolvió qué prop alimenta `panel+0x4b0`
  (el int `cfg+0x48 == 2` que elegiría `0x503100` vs `0x503010`); irrelevante con el
  gate a 0. Si un panel futuro trajera `split-link-enabled`, habría que trazarla.

## 4. Reproducción

```bash
K=~/proyectos/ubuntu-uke/stock/modules/msm_drm.ko
# E4: quién lee la prop (reloc -> string) y dónde se guarda el flag:
readelf -rW $K | grep -E "14fd5c|14fee4|106f2"   # .rodata+0x106f2 = qcom,split-link-enabled
llvm-objdump --arch-name=aarch64 -d --start-address=0x14fd50 --stop-address=0x14fef0 $K
python3 -c "d=open('$K','rb').read();print(d[0x2781a:0x2781a+25])"
# E3: copia panel+0x4a0 -> host_config+0x3c:
llvm-objdump --arch-name=aarch64 -d --disassemble-symbols=dsi_panel_get_host_cfg_for_mode $K | sed -n '/1552a8/,/1552bc/p'
# E1: gate en host_setup:
sed -n '20,33p' build/vendor-re/decomp/dsi_ctrl_hw_cmn_host_setup.c
# DT o82 (ausencia):
P="build/evidencia/android-snap/dt-r15/soc/qcom,mdss_mdp@ae00000/qcom,mdss_dsi_o82_42_02_0b_dualdsi_dsc_vid"
ls $P | grep -ci split; grep -ri split $P $P/qcom,mdss-dsi-display-timings/ ; echo "rc=$?"
```
