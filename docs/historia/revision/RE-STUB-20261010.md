# RE-STUB-20261010: fw mudo por la vía stub-config — comparativa por registro + fix mínimo (alternativa a L13)

Solo-PC (10-oct-2026). Tablet no tocada, sin builds, sin repack, sin ledger.
Estado: **#575 = L11 NO-HFI** (poll vendor sin `L11-pollok`, CM3 suelto,
muerte en `HFI queues -110`) + **#576 = L12 TÓXICO** (el hunk fw-map cuelga
en `L12-fwmap`; a por L13 = hunk-mitad). Este informe ataca el mismo `fw
mudo` por la vía contraria: **config del CM3, no estado del fw**. Si el
body SÍ está en RAM pero el CM3 no lo ejecuta —o lo ejecuta sin señalar—,
los 6 registros de config deciden entre stub desviado y body incomunicado.

## 1. Comparativa por registro: nuestro valor vs vendor

SM7675, familia a7xx como nuestro 732). Nuestro lado: `a6xx_gmu_fw_start()`
(`k52-L11-tree/.../a6xx_gmu.c:1537-1599`, programado ANTES de S1) +
bloque L10-recfg en `a6xx_gmu_start()` (`:781-792`, reprogramado TRAS S1,
estilo C2). Efectivo post-S1 = lo que ve el CM3 al soltar.

nosotros como pre-S1-olvidados.**

## 2. Lente del stub: qué registro puede desviar qué fase (INV-GMU-BIN §2)

- El **stub** (reset `@0x104` → breadcrumb `0x01` → caches+POLL-1/2
  `0x1f40a/0x1f409` → scatter desde el body → `bl 0x4008`) solo consume
  los registros 1–2: BOOT_CONFIG (de dónde fetchea) y CFG (NMI→`@0x144`
  stage 3→WFI; HardFault→`@0x158` stage 4→WFI). FENCE/HFI/GENERAL no los
  toca el stub: ni una lectura.
- El **body** (`__main` en icache) consume 3–7: HFI_QTBL (dónde están las
  colas), GENERAL_8 (dónde loguear), GENERAL_10 (qué chip atiende),
  GENERAL_9 (desde dónde sigue el log), FENCE (ventana AHB hacia DDR).
- Mudo sin cuelgue = el stub terminó en WFI (NMI/HardFault, registros 1–2,
  ya cubiertos por L10) **o** el body corre pero no señala (registros 3–7,
  de los que solo 7 sigue divergente). El breadcrumb post-release (camino
  k61, fuera de este informe) separa ambas ramas en un flash futuro; este
  fix no lo necesita.

## 3. Por qué la vía stub-config es mejor alternativa que L13-hunk-mitad

#576 enseña que el hunk fw-map es tóxico aun siendo "solo-estado": persigue
punteros (`to_msm_vm(gmu->vm)->mmu`), desreferencia RAM del BO
(`virt[0]`) y relee DTCM (`+0xff7`) — algo de eso cuelga tras `recfg-ok`.
Bisecarlo (L13-mitad) sigue jugando en la zona tóxica (structs/RAM).
El fix de §4 es **solo-MMIO en la ventana ya probada**: K44 (12 reads) +
L10-recfg (5 writes + `HFI.iova` struct-read) sobreviven en #574/#575.
Misma esclava GMU, mismo patrón poke+`pr_err`+flush, cero structs
perseguidos, cero RAM, cero SMMU (regla 3 intacta).

## 4. Fix mínimo RS (estilo C2, base L11 — NO L12)

Base: `k52-L11-tree` (el hunk L12 no se hereda). Dos sub-hunks en
`a6xx_gmu_start()`, patrón save/restore calcado de GENERAL_9 (L10):

(a) Pre-S1, junto a la lectura de `gen9_saved` (`:677-682`): guardar
`GENERAL_10/8` (valores que `fw_start` ya dejó; `fw_start` precede a
`start()` en cold Y warm — resume `:1962` → fw_start `:1973` → start
`:1615`; los writes de `:1585-1599` corren en ambos boots, solo `fw_load`
es condicional):

```c
u32 mask, reset_val, val, gen9_saved = 0, gen10_saved = 0, gen8_saved = 0;
...
/* UKE-RS (RE-STUB-20261010): GENERAL_10/8 guardados pre-S1 (valores de
 * fw_start). El vendor los programa TRAS afirmar el reset
 * (register_config); nosotros solo ANTES de S1 y L10-recfg no los
 * reescribe. Si S1 los borra, el fw ve chipid/log=reset -> mudo
 * (pollFAIL+HFI-110 con CM3 suelto, firma #575). Mismo patron que
 * GENERAL_9 (L10): solo MMIO, ventana K44-probada, cero structs/RAM. */
if (adreno_is_a8xx(adreno_gpu)) {
	gen10_saved = gmu_read(gmu, REG_A8XX_GMU_GENERAL_10);
	gen8_saved = gmu_read(gmu, REG_A8XX_GMU_GENERAL_8);
} else if (adreno_is_a7xx(adreno_gpu)) {
	gen10_saved = gmu_read(gmu, REG_A7XX_GMU_GENERAL_10);
	gen8_saved = gmu_read(gmu, REG_A7XX_GMU_GENERAL_8);
} else {
	gen10_saved = gmu_read(gmu, REG_A6XX_GMU_HFI_SFR_ADDR);
	gen8_saved = gmu_read(gmu, REG_A6XX_GPU_GMU_CX_GMU_PWR_COL_CP_MSG);
}
```

(b) Tras S1, después del flush de `recfg-ok` (`:792`) y antes de
`L7-pre-rst` (`:796`): reescribirlos + testigo propio (separado de
`recfg-ok` para atribuir supervivencia a ESTE write):

```c
/* UKE-RS (RE-STUB-20261010): reescribir GENERAL_10/8 tras S1 (ver
 * cabecera pre-S1). Sin esto el body arrancaria con chipid/log a reset. */
if (adreno_is_a8xx(adreno_gpu)) {
	gmu_write(gmu, REG_A8XX_GMU_GENERAL_10, gen10_saved);
	gmu_write(gmu, REG_A8XX_GMU_GENERAL_8, gen8_saved);
} else if (adreno_is_a7xx(adreno_gpu)) {
	gmu_write(gmu, REG_A7XX_GMU_GENERAL_10, gen10_saved);
	gmu_write(gmu, REG_A7XX_GMU_GENERAL_8, gen8_saved);
} else {
	gmu_write(gmu, REG_A6XX_GMU_HFI_SFR_ADDR, gen10_saved);
	gmu_write(gmu, REG_A6XX_GPU_GMU_CX_GMU_PWR_COL_CP_MSG, gen8_saved);
}
uke_poke("RS-recfg2");
pr_err("UKE-RS: recfg2-ok\n");
pr_flush(120, false);
```

Nomenclatura propuesta: **L13s** (árbol `k52-L13s-tree`, patch
`k52L13s-stubcfg.diff`, tag `k52L13s`, testigos `RS-recfg2` /
`UKE-RS: recfg2-ok`) para no colisionar con el L13-hunk-mitad del ledger;
el coordinador decide si lo sustituye o va como L14. NO se tocan: L10-recfg,
poll vendor, HFI, GENERAL_9, GENERAL_11, lógica. Gates a añadir al clon de
`build-k52L11.sh`: fuente RS-SAVE/RS-RESTORE; binario `RS-recfg2` +
`UKE-RS: recfg2-ok` x1 + **POKE 113→114** (cada `uke_poke` añade un literal
`UKE-POKE`, `uke-panic-fb.c:257`; el repack G3 debe esperar 114) + gate
L11-WRITE intacto (1 `str` al MMIO entre pre-rst y write-done).

## 7. Notas honestas

- Bits de BOOT_CONFIG y semántica allow/deny del FENCE sin documentar en
  árbol, xml ni vendor: sus filas concluyen "idéntico al vendor", no
  "correcto para el 732 por spec".
- Que el fw gatee `INIT_RESULT` en chipid/log es inferencia (sin fuente del
  fw): el flash de §5 la confirma o la mata en UN intento.
- Que S1 borre GENERAL_10/8 es la hipótesis que el flash decide; si los
  conserva, el fix es inocuo por construcción (reescribe los mismos
  valores) y el veredicto cae a la fila 2 de §5.
- Considerado y descartado: `GENERAL_7`/TCM-retención (vía CX_MISC, otro
  bloque; la TCM retiene: ITCM/DTCM leídos OK) y `power_config`/GBIF_CX
  (fase de potencia: fallarían en hang, no en mudo).
